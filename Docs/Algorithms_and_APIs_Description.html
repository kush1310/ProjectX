2. Authentication & Security Algorithms

2.1 JWT (JSON Web Token) — HS256 HMAC Algorithm

JwtService.javaAuthService.java

What it is: JWT is an open standard (RFC 7519) for securely transmitting information between parties as a JSON object. The token is digitally signed using HMAC-SHA256.

How it works:

  • Token Generation: When a user logs in, the server creates a JWT containing claims (userId, email, role) and signs it with a 256-bit secret key using HMAC-SHA256.
  • Token Structure: Header (algorithm + type) + Payload (claims + expiry) + Signature — all Base64-encoded and separated by dots.
  • Validation: On each request, the JwtAuthenticationFilter extracts the token from the Authorization header, verifies the signature and expiration, and loads the user into Spring Security context.
  • Expiry: Tokens expire after 24 hours (86,400,000 ms) to limit exposure if compromised.

2.2 BCrypt Password Hashing Algorithm

SecurityConfig.javaPasswordPolicyService.java

What it is: BCrypt is an adaptive cryptographic hash function designed for password storage. It incorporates a salt to protect against rainbow table attacks.

How it works:

  • When a user registers, their plaintext password is hashed using BCrypt with a random 128-bit salt and a cost factor (default 10 rounds = 210 iterations).
  • Only the hash is stored in the database — the original password is never saved.
  • During login, BCrypt re-hashes the input with the stored salt and compares the results in constant time to prevent timing attacks.
  • BCrypt is deliberately slow, making brute-force attacks computationally expensive.

2.3 Google OAuth 2.0 (Authorization Code Flow)

GoogleAuthService.java

What it is: OAuth 2.0 (RFC 6749) allows users to log in using their Google account without sharing their password with our application.

How it works:

  • Step 1: User clicks "Sign in with Google" — the frontend redirects to Google's consent screen.
  • Step 2: Google returns an authorization code to the redirect URI (/auth/callback).
  • Step 3: Backend exchanges the code for an access token via Google's token endpoint using RestTemplate.
  • Step 4: Backend uses the access token to fetch user profile (email, name, picture) from Google's UserInfo API.
  • Step 5: If the email domain is valid (e.g., @charusat.edu.in), the system finds or creates the user and issues a JWT.

2.4 Refresh Token Rotation Algorithm

RefreshTokenService.java

What it is: A security mechanism (RFC 6749, OWASP guidelines) where refresh tokens are single-use and rotated on each use.

How it works:

  • A 64-byte cryptographically secure random token is generated using SecureRandom.
  • The token is hashed with BCrypt before storage — only the hash is saved in the database.
  • When the access token expires, the client sends the refresh token. The server validates it via BCrypt matching, revokes the old token, and issues a new token pair.
  • Max 5 active tokens per user; oldest tokens are auto-revoked. Tokens expire after 30 days.
  • IP and device tracking detects potential token theft (token used from a different IP).

2.5 Progressive Account Lockout Algorithm

AccountLockoutService.java

What it is: A brute-force prevention mechanism following OWASP A07:2021 guidelines with escalating lockout durations.

How it works:

  • Failed login attempts are tracked per user (email) and per IP address within a 15-minute sliding window.
  • Progressive lockout: 5 failures → 5 min lock, 10 failures → 15 min lock, 15+ failures → 1 hour lock.
  • IP-based rate limiting: 20 failed attempts from any single IP triggers an IP block.
  • After 3 failures, CAPTCHA verification is required before allowing further login attempts.
  • Lockout resets immediately after a successful login.

2.6 NIST 800-63B Password Policy Algorithm

PasswordPolicyService.java

What it is: Password strength enforcement following NIST Digital Identity Guidelines.

Rules enforced: Min 8 chars, max 128 chars, at least 1 uppercase, 1 lowercase, 1 digit. Common passwords (e.g., "password", "123456") are blocked. Password cannot contain the username.

Password History: Last 5 passwords are stored as BCrypt hashes. Users cannot reuse recent passwords.

Strength Scoring (0–100): Length contributes up to 40 points (4 pts/char); each complexity category (uppercase, lowercase, digit, special) adds 15 points.

2.7 CAPTCHA Generation Algorithm

CaptchaService.java

What it is: Server-side CAPTCHA generation using Java 2D Graphics API to prevent automated login attacks.

How it works:

  • A 6-character random code is generated from an ambiguity-free character set (excludes I, O, 1, 0).
  • A 160×50 pixel image is rendered using Java2D with random noise lines, random text colors, and slight vertical offsets for each character.
  • The image is encoded as Base64 PNG and sent to the client. The code is stored in a ConcurrentHashMap with a UUID key and 5-minute TTL.
  • Validation is one-time-use and case-insensitive. Expired entries are cleaned every 10 minutes by a scheduled executor.

5. Business Logic Algorithms

5.1 Coupon Validation Engine (10-Step Sequence)

CouponValidationService.java

A rule-based validation pipeline that checks coupons in this exact order:

  1. Existence: Coupon code exists in the database.
  2. Active Status: Coupon is currently enabled (not paused).
  3. Date Validity: Current time is between start and end dates.
  4. Global Usage Limit: Total redemptions haven't exceeded the maximum.
  5. Per-User Usage Limit: This specific user hasn't exceeded their allowed uses.
  6. Minimum Order Value: Cart total meets the coupon's minimum threshold.
  7. Item Applicability: For ITEM_SPECIFIC coupons, at least one applicable item is in cart.
  8. Combo Validation: For COMBO coupons, all required combo items are present.
  9. Rush Hour Window: For RUSH_HOUR coupons, current time falls within the specified window.
  10. New Customer Check: For new-customer-only coupons, user has zero prior orders.

5.2 Discount Calculation Algorithm

CouponService.java

Supports multiple discount strategies:

  • PERCENTAGE: discount = orderTotal × (percentage / 100), capped at maxDiscount.
  • FLAT: discount = fixed amount, cannot exceed orderTotal.
  • BOGO (Buy One Get One): Identifies the cheapest qualifying item and applies it as the discount.
  • COMBO: Applies a fixed combo discount when all required items are in the cart.

5.3 Best Coupon Suggestion Algorithm

CouponService.java — suggestBestCoupon()

How it works: Iterates through all active coupons for the canteen, validates each against the current cart, calculates the potential discount, and returns the coupon offering the maximum discount amount. This is a greedy optimization approach — O(n) where n = number of active coupons.

5.4 Order Processing Pipeline

OrderService.java

  • Generates a unique order number using UUID (ORD-XXXXXXXX).
  • Validates all menu items and calculates subtotal.
  • If a coupon code is provided, runs the full validation engine and applies discount.
  • Saves order with items, records coupon usage, and sends real-time WebSocket notification to vendor.
  • Order follows a state machine: PENDING → CONFIRMED → PREPARING → READY → COMPLETED (or CANCELLED).

5.5 Analytics Computation Algorithms

CouponAnalyticsService.java

  • Sales vs Discount: Groups coupon usage by time period (weekly/monthly/yearly) and aggregates total sales and discounts using Java Streams with groupingBy collectors.
  • Vendor Impact: Calculates revenue impact per vendor — total orders, discount given, and ROI.
  • Type Performance: Aggregates usage count, total discount, and average discount per coupon type.
  • Customer Analytics: Identifies top users by redemption count and total savings.
