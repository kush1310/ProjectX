schema changes, API requirements, and frontend/backend strategy for the 15 change

4. CHANGE PASSWORD OPTION FOR AUTHENTICATED USERS
--------------------------------------------------------------------------------
Goal:
Allow logged-in users (Students, Vendors, Admins) to securely change their password from profile settings.

Requirements:
- Separate from the unauthenticated Forgot Password OTP flow.
- Must verify the user's current password before allowing change.
- Enforce NIST 800-63B policy: 8-128 chars, uppercase, lowercase, digit requirement.
- Perform historical check against `password_history` (prevent re-using last 5 passwords).
- Update `last_password_change` timestamp in `users` table.

Implementation Checklist:
[Backend] Create `POST /api/users/change-password` endpoint in `UserController.java`.
[Backend] Verify current password with `BCryptPasswordEncoder`.
[Backend] Store new hash in `password_history` and purge entries beyond 5.
[Frontend] Add "Change Password" section in `CustomerProfile.tsx` and `VendorProfile.tsx` with PasswordStrength meter.

15. ARCHITECTURAL OVERHAUL — ON-DEMAND / LAZY LOAD STRATEGY (HIGH PRIORITY)
--------------------------------------------------------------------------------
Goal:
Eliminate initial upfront loading of all application tabs and data. Achieve instant app startup.

Strategy & Rules:
1. Initial Load: Load ONLY the Login screen (`/login`) or Landing Page (`/`).
2. Post-Authentication: Load ONLY the primary dashboard shell for the logged-in role (`/customer/dashboard` or `/dashboard`).
3. Zero Eager Tab Pre-fetching: Tabs (Menu, Reviews, Complaints, Analytics, Coupons, Payouts) must NOT be loaded into memory or state until the user actively clicks into them.
4. Route Code-Splitting: Enforce `React.lazy()` with route-level `Suspense` fallback for every tab.
5. On-Demand Data Fetching: Each page component triggers its own API call inside `useEffect` upon mounting, displaying accurate skeletons during fetch.

Implementation Checklist:
[Frontend] Refactor `App.tsx` routing to verify strict code-splitting per tab.
[Frontend] Audit `Dashboard.tsx`, `StudentDashboard.tsx`, and `VendorLayout.tsx` to remove eager state pre-fetching.
[Frontend] Enforce component-level fetch on tab mount.
